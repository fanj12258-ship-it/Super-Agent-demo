动效节奏

  • 常态只有「施工中」那一块在动(描边流动),侧栏小图没有光点。
  • 光点上升只在展开的大图里出现,避免侧栏同屏抢戏。
  • 状态切换 400–500ms 缓动;prefers-reduced-motion 下全部静止,只保留颜色。

尺寸与降级

  • 侧栏小图高度约 150px,不带说明文字,名字只在右侧留一列短标签。
  • 侧栏宽度 < 240px:收起图,只剩列表。
  • 尚未进入场景(Overview 状态)时整块不出现,和现在的行为一致。

接到产品页的方式

  • 数据源不变:FastBlueprint.set(node, state, text) 同时驱动图和行。
  • 现有 #fast-bp 里的节点卡片会被「图 + 行」替换,行的状态样式沿用现在的 doing / done / optional。
  • 展开层属于中间区域的组件,Fast 页的对话脚本不需要改。

0 · 现状(扁平卡片)

已上线的 Fast 页版本,放这里做对照。

A · 等轴堆叠(5 层盖楼)

五块悬浮板自下而上叠起,右侧用引线标注。施工中的板抬起并蓝色描边,盖好的变实体。

B · 平台图(留给场景详情 / Agent 概览)

需求和知识是输入,设计文档是核心板。本体在左上;Skill 接在通往 Agent 的路径上,Agent 抬高,并与设计文档同大。

状态语言(A、B 通用)

  • 线框虚线 = 还没建;更淡的虚线 = 可选,不阻塞。
  • 蓝色 + 抬起 + 描边流动 = 本轮对话正在施工。
  • 实体灰 + 绿色点缀 = 已建好。
  • 连接线:下层建好后,线变深并有光点向上流动,表示「喂给上一层」。

想和你深聊的几点

  • A 还是 B? A 进度感强、一眼看出建到哪;B 更优雅、更像 Palantir,但 5 个节点压成 3 段,「需求 / 知识」要并排。
  • 本体、Skill 放哪? A 里是同一块板上的两个小格;B 里本体单独在左上,Skill 在通往 Agent 的路径上,Agent 抬高并与设计文档同大。
  • 状态文字保不保留? 现在是每块板配一行「待传合同」这类文字,去掉会更纯粹但信息少。
  • 点击行为: 点板块后是跳到 Files 里的对应交付物,还是在中间对话里滚到相关消息?
  • 配色: Palantir 是灰 + 薄荷绿,我们现在是灰 + 蓝(施工)+ 绿(完成)。要不要换成更克制的单色?

落地成本与风险

  • 纯 SVG + CSS,不引库;状态切换已经抽成同一个数据结构,和 FastBlueprint.set(node,state,text) 能直接对上。
  • 窄屏:按容器宽度重新计算板的大小,标注列固定约 112px;宽度 < 280 时 A 需要把标注折到板下方。
  • 高度:A 约 450px,需要在侧栏内滚动;B 把 Agent 抬到 Skill 之上后大约 650px,侧栏里需要滚动。
  • 无障碍:SVG 内文字可读,另需一份隐藏的列表语义给读屏软件。
  • 这份讨论稿是独立文件,不影响 superagent.html 和 superagent-fast.html。

模式对照 · Fast / Steps 横向 · 只有模块层，没有文档层

两种开始方式的结构对比。Fast（现在叫「轻量模式」）先走一条快速通道出一版 Agent，再回头把 Mock 逐项补实；Steps（「按流程打造」）按八步顺序一步步做扎实。这里去掉了下面的文档层，只看结构差别。

Fast 轻量模式

对齐需求后，中间的知识、设计、本体、Skill 先用 Mock 顶上，直接生成一版可试用的 Agent；试用中发现不足，再回头把 Mock 逐项换成真实实现。

Steps 按流程打造

按八步顺序推进：理需求 → 挖业务知识 → 产品 / 本体 / Agent 三份方案 → 建本体 → 打造 Skill、MCP 等资源 → 生成 Agent。每一步确认后再进入下一步。
