01 · SUMMARY一页读懂

如果只有三十秒，请读这一节。

一句话：工作台是“项目空间的总览与调度台”。它回答三个问题——这个项目里有什么资产？每个场景做到哪一步了？下一步该点哪个按钮？

真正动手“造”东西的地方是工坊（Workshop），工作台负责把人带到正确的工坊入口，并保证回来时一眼看懂现状。

它是什么

一个项目空间的“资产与进度总览”

  • 左侧 8 个入口：Scenario / Agent / Knowledge Base / Skill / Ontology / MCP / Files，外加 Market、AI Ops（即将上线）
  • 右侧是对应资产的卡片墙（Files 为文件列表）
  • 顶部固定两件事：进入工坊、导入 Agent
  • 底部是账号与通知
它和旧版的区别

从“列表页”变成“带下一步的总览”

  • 场景卡按阶段自动给出唯一最合适的下一步（开始 / 继续 / 去上线 / 迭代）
  • 一张卡片同时展示四类资产的就绪度（绿 / 橙 / 灰点）
  • 导航分成 Workspace（本项目资产）与 Explore（发现与运营）
  • 导航图标统一成同一套线性图标，通知面板更宽、更适合读内容

三条最重要的设计决定

  1. 按钮由“阶段”决定，而不是由“页面”决定。同一张卡片上，主按钮永远只有一个，且文案随阶段变化：Start crafting → Continue crafting → Go to launch → Iterate。用户不需要自己判断“现在该干嘛”。
  2. 资产结构始终可见。场景是由本体、技能、知识库、Agent / MCP 组装起来的，卡片上用四个小圆点直接亮出每一块“做到了没有”，不用点进去才知道缺什么。
  3. 阶段只用定性词，不用假进度。只有 Not started / Crafting / Ready / Live 四个词，没有“65%”这种看似精确、实际无法兑现的数字。

02 · WHY为什么这样设计

先讲定位，再讲痛点，最后讲它带来的好处。

2.1 工作台与工坊：两个房间，各司其职

AgentOS 里制作 Agent 的过程分成两个空间：

工作台 Workbench

外层壳。管理项目空间、各类资产目录、账号与通知。回答“有什么、到哪了、下一步去哪”。

⇄
工坊 Workshop

内层制作间（superagent/）。对话式搭建、双模式制作、逐步确认。回答“怎么把它做出来”。

两者之间只靠几个明确的动作连接：Enter Workshop（进入工坊总览）、Start / Continue crafting（进入对应场景继续制作）、Go to launch / Finalize（进入定稿 / 上线环节）、Iterate（对线上已有的场景发起迭代）。

2.2 为什么要这样拆

拆之前的问题
  • “制作”和“管理”混在同一个界面，既要看全局又要专注细节，两头都不好
  • 用户回到项目时不知道从哪接着做，要靠记忆或翻记录
  • 资产（本体、技能、知识库…）是分散的，一个场景用了哪些、缺哪些，没有地方能一眼看到
  • “Live（已上线）”的东西再点“去制作”，语义是错的——它应该是“迭代”
拆之后的好处
  • 进来就知道现状：每个场景的阶段、资产就绪度、业务场景进展都在首屏
  • 下一步唯一：一个主按钮，减少决策成本，新同事也不会点错
  • 资产可复用、可追溯：四类资产有各自的目录页，场景引用它们
  • 制作间保持专注：工坊只承载“做”，不被管理类信息打扰

2.3 制作逻辑如何影响了工作台的样子

工作台不是孤立设计的，它背后是工坊的产品逻辑（参见 superagent/DEMO-JOURNEY.md）：

工坊里的逻辑在工作台上的体现
双模式制作
快速 POC 路径 + 保留的四步正式路径，二者可互通、可一键同步		工作台不区分用户走哪条路径，只呈现统一的阶段（Crafting / Ready / Live）。无论怎么做，回到工作台看到的都是同一套状态词。
资产结构可见场景卡上的四枚资产圆点（Ontology / Skill / Knowledge / Agent 或 MCP）与“3 ready · 1 in progress”汇总。
Live = 迭代，而不是“去制作”阶段为 Live 时，主按钮变为浅色的 Iterate，视觉上也降一级，提示“这是线上稳定态，改动要谨慎”。
只用定性阶段，不造假进度阶段胶囊只有四个词；没有百分比、没有进度条。
逐步确认Ready 阶段的主按钮是 Go to launch（应用级）或 Finalize（业务场景级），把“确认并发布”变成一个有意识的动作。

03 · PRINCIPLES设计原则

每一条都对应页面里可以指出来的具体做法。

原则含义页面里的体现
1 · 下一步唯一任何一张卡片上，“主要行动”只有一个，且由状态决定。场景卡主按钮随阶段变；Agent 卡按钮随状态变（Try / Go to publish / Continue building）。
2 · 状态用颜色 + 文字，永不单靠颜色色盲友好，也方便截图沟通。阶段胶囊 = 彩色圆点 + 文字；资产点配有名称。
3 · 一套语义色贯穿全站绿 = 已上线 / 已就绪；蓝 = 待确认 / 可发布；橙 = 进行中；灰 = 未开始。场景阶段、Agent 状态、资产点、知识库同步点都用同一套色。
4 · 克制主色用近黑 #171717，彩色只留给“状态”；装饰只出现在空状态页。内容页保持纯白；仅 Market / AI Ops 使用淡色渐变与插画。
5 · 浮层同一套语言所有弹出层共用同一圆角、阴影、字号、行高。项目菜单、账号菜单、通知面板同一个视觉源头（popover tokens）。
6 · 动效克制只做反馈，不做表演；时长不超过 0.14 秒。hover、选中、展开均为极短过渡。
7 · 诚实没做的就标明没做，不用假数据装作已完成。Market / AI Ops 明确写 “Coming soon”，主按钮置灰。

04 · LAYOUT整体布局

左窄右宽，左边是“去哪”，右边是“有什么”。

  1. 项目切换当前项目空间名 + 彩色首字母头像；点开可切换或新建。
  2. Enter Workshop近黑实心按钮，侧栏里唯一的实心按钮，进入工坊。
  3. Import Agent虚线描边的次要按钮，导入已有 Agent 包。
  4. Workspace 导航本项目的 7 类资产入口，选中项浅蓝底 #e5f4ff；Scenario 行右侧的 + 用于就近新建场景。
  5. Explore 导航Market、AI Ops：不属于本项目资产，属于“发现与运营”。
  6. 账号头像 + 用户名，点开账号菜单。
  7. 通知铃铛点开通知面板。
  8. 顶栏左侧 ‹ › 切换页面，其后是当前页面名；与内容区共用同一背景。
  9. 页面标题 + 说明说明里自带项目名（如 “DJI Innovations · …”），提醒当前作用域。
  10. 工具栏左：条目数；右：All / Recent 切换芯片。
  11. 内容网格三列卡片墙，卡片间距统一。

尺寸规范

部位规格说明
侧边栏宽度256px固定，不随内容伸缩，保证所有项目空间下导航位置恒定（肌肉记忆）。
顶栏高度54px仅承载切换与当前页名，不放操作按钮。
主区内边距32px卡片墙与标题对齐同一左边线。
正文字号Inter 12 / 16高密度信息工具的标准字号；弹层内为 13px。

05 · NAVIGATION侧边栏与顶栏

侧边栏从上到下是：品牌 → 项目 → 两个全局动作 → 资产导航 → 发现与运营 → 账号。

  1. 品牌区AgentOS 标识 + “1.0 beta” 标签，仅展示，不可点击。
  2. 项目切换器头像用该项目的专属颜色。右侧小箭头提示“可展开”。悬停浅灰底，展开时保持浅灰。
  3. Enter Workshop左侧带向右箭头，意为“前往”。是侧栏里唯一的实心黑按钮。
  4. Import Agent虚线框 + 上传箭头：表达“把外部东西放进来”。比实心按钮弱一级。
  5. WORKSPACE 分组标签大写小字灰色，只做分组，不可点击。
  6. Scenario（选中态）浅蓝底 + 图标文字加深。始终排第一位，因为它是整个项目的“主线”。
  7. + 新建场景悬停出现浅灰底；点击不会切换页面，直接弹出“新建场景”窗口。
  8. FilesWorkspace 分组的最后一项：文件是所有资产的“底层素材”。
  9. EXPLORE 分组标签与上方用一条细分隔线隔开。
  10. Market发现可复用的 Agent、Skill、MCP 包。
  11. AI Ops上线后的运行健康与追踪。
  12. 账号红色头像 + 用户名。
  13. 通知铃铛线框铃铛；点开后图标按钮进入“已按下”背景态。

5.1 为什么分成 Workspace 与 Explore

Workspace 里的都是“属于这个项目空间”的东西——切换项目，列表就跟着变；Explore 里的是“跨项目、面向发现与运营”的入口。把它们分开，用户不会误以为 Market 里的内容是自己项目的资产。

5.2 导航顺序的逻辑

Scenario → Agent → Knowledge Base → Skill → Ontology → MCP → Files。按“从业务目标到交付物，再到支撑它们的素材”排列：先看场景（做什么），再看产出的 Agent，再看供给它们的知识、技能、本体与工具，最后是文件。

5.3 顶栏：‹ › 页面切换

Scenario　← 当前页面名随切换同步变化

顶栏左侧的 ‹ › 与浏览器前进后退类似，用于在资产页之间顺序切换，不依赖鼠标回到侧栏。切换顺序（循环，首尾相接）：

Scenario→Agent→Skill→Ontology→MCP→Files↻ Knowledge Base *Market *AI Ops *

已知细节（如实说明）：当前的循环顺序里没有包含 Knowledge Base，也不包含 Market / AI Ops（虚线灰色项）。它们只能从侧栏进入。这是 Demo 阶段的遗留，是否补上，需要产品确认后再决定（工作台版本已锁定，需明确指示才会修改）。

06 · POPOVERS三个弹层：项目 / 账号 / 通知

三者共享同一套弹层样式（圆角 14、淡阴影、白底、13px 字号、34px 行高），位置都锚定在侧栏。

6.1 项目切换菜单

  1. 触发器展开时保持浅灰底，表示“这个菜单属于我”。
  2. 当前项目右侧对勾 ✓ 标记当前项。
  3. 其他项目点击即切换：侧栏项目名、头像颜色、主区标题说明中的项目名同步更新，并保持当前所在页面不变。
  4. New project space虚线圆圈 + 号，弱化为“创建类”选项。输入名称后自动生成首字母头像并分配颜色，随即切换进去。

设计意图：菜单在触发器下方展开（项目在侧栏顶部），宽度与侧栏一致，让它看上去是侧栏的一部分，而不是另一个窗口。

6.2 账号菜单（含中 / 英切换）

  1. 身份头大头像 + 用户名 + 邮箱。
  2. Language 语言“中 / EN” 分段开关，选中项白底浮起。切换只作用于菜单内文案，并记住选择。
  3. Profile 个人资料
  4. Version update 版本更新
  5. 红点提示有新版本。
  6. Log out 退出登录与上方两项用细线隔开，位置在最底。

设计意图：菜单在触发器上方展开（账号在侧栏底部）；点击任意菜单项、点击空白处、按 Esc 都会关闭。

6.3 通知面板

  1. 标题仅一个 “Notifications”，无多余按钮。
  2. 通知条目头像 · 姓名 · 时间 · 动作文案，每条左右留 16px 内边距。
  3. 头像用发送者的专属颜色 + 首字母。
  4. 时间近期用相对时间（2h / 5h / 1d），更早用日期（Oct 8）。
  5. 动作文案统一句式“动词 + 资产类型 · 资产名”，例如 Published doc · Sourcing playbook。
  6. 长文案评论类通知文字较长，最多显示 2 行，超出以省略号截断。
  7. 铃铛（按下态）面板打开期间保持高亮。

为什么通知面板比账号菜单宽：账号菜单和项目菜单内容很短，严格对齐侧栏宽度会更整齐；但通知里有句子，对齐侧栏会让文字被挤成三四行。所以通知面板只在宽度上突破侧栏（宽 360px，高度最多 560px 或视窗减 72px），左边沿与其他弹层保持一致，改为内容可读性优先。

Demo 中放了 14 条模拟通知，列表可滚动，用来验证长列表下的观感。

07 · SCENARIOScenario 场景（核心页）

这是工作台里信息量最大、设计投入最多的一页：一张卡片就是一个“应用场景”的完整档案。

7.1 场景卡片解剖

  1. 类型标签 Application淡紫底紫字。表示“应用场景”，下方的叫“业务场景”。
  2. 阶段胶囊整个场景所处阶段（Not started / Crafting / Ready / Live）。
  3. 场景名称
  4. 描述最多两行，超出省略。
  5. 资产小圆点四个药丸：每个含“圆点 + 资产类型”，悬停可看到具体资产名。绿 = 已完成、橙 = 进行中、灰 = 尚未开始。
  6. 资产汇总如 “3 ready · 1 in progress”，用文字把四个圆点再说一遍。
  7. 主 CTA随阶段变化（见 7.3）。
  8. 业务场景小标题“Business scenarios · 3”，带数量。
  9. 业务场景行应用场景下的子场景，白底小卡，在浅灰区域内。
  10. 优先级Quick win / Important / Long-term，蓝灰色小标签。
  11. 业务场景阶段与应用场景同一套阶段胶囊。
  12. 行级按钮描边按钮（ghost），比主 CTA 弱一级。
  13. Show N more默认只显示 2 条，更多折叠在虚线按钮后。

7.2 层级关系：一个应用，多个业务场景

应用场景 Application

对应一个 AgentTeam（多 Agent / 角色协作）。拥有资产集合与整体阶段。

→
业务场景 Business

对应单个 Agent，解决一个具体问题。拥有自己的阶段与优先级。

→
资产 Assets

Ontology · Skill · Knowledge · Agent / MCP，被场景引用并被卡片可视化。

这解释了卡片上下两层的原因：上层是整体（给负责人看：整体能不能上线），下层是拆分后的具体工作项（给执行人看：我该继续哪一个）。

7.3 阶段 → 按钮：一张对照表

阶段应用场景（卡片底部）业务场景（行内）语义
Not startedStart craftingStart crafting还没开始，引导用户开始制作。
CraftingContinue craftingContinue crafting做到一半，回到工坊续做。
ReadyGo to launchFinalize已就绪、待确认。应用级是“去上线”，业务场景级是“定稿”。

只有应用场景的主 CTA 是实心黑色（Live 除外）；业务场景行内按钮一律为描边。这样一屏里最醒目的按钮总数很少，视线不会被分散。

7.4 阶段与资产点的关系

阶段是人为的整体判断，资产点是客观的零件状态，两者相互印证：

  • Live 的场景（如 Sales enablement suite）资产点几乎全绿；
  • Not started 的场景（如 Incident command center）资产点以灰色为主，其中有一个橙点说明“已经有人开始准备知识库了”；
  • 资产汇总 “0 ready · 1 in progress” 可以直接解释为什么还没开始。

7.5 展开 / 收起业务场景

  • 业务场景默认最多显示 2 条，其余折叠，避免一张卡片过长、破坏三列网格的整齐。
  • 展开后虚线按钮变成实线 Show less，点击收起。
  • 展开 / 收起只影响当前这一张卡片，不影响其他卡片。
  • 数量够少（≤2）的卡片没有这个按钮，也不留空位。

7.6 工具栏：条目数与 All / Recent

工具栏左边显示 “6 items in DJI Innovations”（含项目名，强化作用域），右边为 All / Recent 两个芯片，当前选中项为黑底白字。该工具栏在 Agent / Knowledge Base / Skill / Ontology / MCP 页同样出现，用于统一“看列表”的体验。（All / Recent 目前为展示，尚未接入过滤。）

08 · AGENT & ASSETSAgent 与四类资产页

五个页面使用同一套三列卡片网格，但每种资产用最适合它的“预览方式”来区分，让用户不用读字就能认出自己在哪一页。

8.1 Agent

  1. 首字母头像方形圆角，每个 Agent 有自己的专属色，便于一眼辨认。
  2. 名称
  3. 角色描述最多两行。
  4. 模型灰色标签，如 qwen3.7-max、deepseek-v4-pro、glm-5.3-flash。
  5. 能力标签如 Single agent / Multi-agent、Autonomous planning / Workflow。
  6. 状态圆点 + 文字：Live（绿，外圈光晕）/ Ready（蓝）/ Draft（灰）。
  7. CTA由状态决定，见下。

三种状态与对应按钮：

关键约定：卡片本身不改变状态。Ready → Live 需要“去发布”，由系统配置页来完成；工作台只是把你送过去（点击 Go to publish 的提示语即写明 “status is changed there, not on this card”）。这样可避免在总览页误触造成上线。

8.2 Knowledge Base 知识库

  1. 文档预览用叠放的“纸张”示意，一张后置、一张前置，灰条模拟文字——一眼看出这是“文档集合”。

  3. 名称
  4. 同步元信息状态点 + 分块数 + 同步时间；绿点 = 正常，橙点 = 索引中或排队中（如 “Indexing…”、“Index queued”）。

8.3 Skill 技能

  1. YAML 头预览直接把技能文件的 front-matter（name / version / description / tags）以代码样式展示，让工程同事一眼认出“这是个 Skill 文件”。语法着色：键名蓝、值绿、分隔线灰。
  2. 标题
  3. 版本号如 V5.0，灰底小标签。
  4. 描述最多两行。
  5. 更新时间
  6. 标签与 YAML 里的 tags 一一对应，方便检索与复用。

8.4 Ontology 本体

  3. 描述
  4. 最后更新“Updated by 谁 · 何时”，强调协作责任人。
  5. 发布状态Draft（蓝色标签）/ Published（绿色标签）。
  6. 版本数“2 versions”，本体强调版本沿革。

  2. 名称
  3. 描述
  4. 更新时间

  5. 体积如 4.7 MB。

10 · EXPLOREMarket 与 AI Ops（即将上线）

它们还没有真实功能，但不是一片空白——用“空状态”清楚地告诉用户：这是什么、将来能做什么、现在不能点。

  1. 插画淡色线性插画：Market 是三张重叠的卡片（一张选中、带勾）；AI Ops 是一块带心跳折线的面板，左侧环形进度、右侧三色状态点。
  2. Eyebrow“COMING SOON · MARKET / AI OPS”，大写小字，明说“尚未上线”。
  3. 标题Market：Discover agents built for your team；AI Ops：Keep every agent run in view。
  4. 说明一句话讲清价值。
  5. CTA（置灰）Browse Market / Open AI Ops，不可点击，带一个下拉小箭头，预告“将来会有菜单”。
  6. 脚注“… is coming soon in this demo”。
  7. 顶栏同色贯通渐变覆盖整个右侧区域（含顶栏），没有断层或接缝。

为什么只有这两页有色彩：内容页（Scenario、Agent…）全部使用纯白，信息才是主角；而空状态页没有信息，需要一点“气氛”来承接用户的好奇。因此有内容 = 白，无内容 = 淡色渐变 + 插画，这样用户一进页面就能判断“这页有没有东西”。

两种色相与语义呼应：Market 蓝（发现、选择），AI Ops 绿（健康、运行）。

14 · WHAT CHANGED相比旧版改了什么

对比基准：本轮改版开始时的版本（2026-10-10 下午）与现在的锁定版。

#改动点之前现在为什么
1场景卡的主按钮统一叫 “Go to craft”，所有阶段都一样随阶段变：Start / Continue crafting、Go to launch、Iterate；业务场景行为 Finalize 等让用户不用判断下一步；Live 态改用 Iterate 表达“迭代”的语义。
2侧栏分组Market 与 AI Ops 各自被分割线隔开，没有分组名称新增 WORKSPACE / EXPLORE 两个分组标签，Market 与 AI Ops 合并为一组明确“项目内资产”与“发现运营”的边界。
3导航图标各处风格不一的图标统一为锁定的线性家族：24 网格、18px、描边 1.5、圆角端点视觉重量一致，并与工坊启动器共用一套。
4Scenario 图标类似“图片”的矩形图标三层叠放的菱形更贴近“场景由多层构成”的含义。
5项目切换与按钮密度项目行、按钮更松项目行更紧凑，两颗按钮间距更小把更多空间留给导航，减少首屏拥挤。
6Market / AI Ops 页面淡渐变只在顶栏以下，顶栏处断开；无插画全幅淡色渐变（含顶栏，无接缝）+ 插画 + “Coming soon” 标签空状态更有质感，同时坦诚告知未上线。
7通知面板与侧栏等宽，内容被挤压宽 360px，更高、可滚动；长文案限制 2 行；14 条模拟数据通知是“读内容”，需要比菜单更宽的空间。
8内容页背景—明确保持纯白试验过淡色背景，用户体验后选择回到白色。
9工程结构一个大 HTML拆成 css/（10 个文件）+ js/（8 个文件）与 superagent 一致，便于协作与维护；拆分后视觉与行为经对比验证一致。
10版本锁定—2026-10-10 起锁定，附带备份没有明确指示，不再修改。
